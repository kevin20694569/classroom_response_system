# Quickstart：使用者角色與老師端搶答活動管理

**Feature**: `001-teacher-quiz-session`

本文件說明如何在本機啟動系統、執行自動化驗證，以及進行人工驗證（constitution 原則 VII）。
API、事件與辨識規則的細節請見 [contracts/](./contracts/) 與 [data-model.md](./data-model.md)。

## 1. 事前準備

只跑自動化測試時，只需要完成 1.1；要連線真實 Google Sheets（人工驗證、Demo）才需要 1.2～1.4。

### 1.1 Node.js 26 LTS

在專案根目錄執行（版本依 `.nvmrc`）：

```bash
nvm install && nvm use
```

`node -v` 應顯示 `v26.x.x`。

### 1.2 建立 Google 服務帳號與金鑰

系統以**服務帳號**（service account）的身分讀寫 Guided Notes。服務帳號是一個專屬於本系統的
Google 機器人帳號，有自己的 email，你把試算表分享給它，它就能讀寫那份試算表；系統不會用你自己的
Google 帳號登入，也不需要設定 OAuth 同意畫面。啟用 Google Sheets API 與建立服務帳號都不需要綁定信用卡。

> 建議使用**個人 Gmail 帳號**操作。學校的 Google Workspace 帳號可能被組織政策禁止建立服務帳號金鑰
> （錯誤訊息會提到 `iam.disableServiceAccountKeyCreation`），遇到時請改用個人帳號。

1. **建立專案**
   1. 開啟 [Google Cloud Console](https://console.cloud.google.com/)，用你的 Google 帳號登入。
   2. 點畫面上方的專案選擇器 → 「新增專案」。
   3. 專案名稱填 `classroom-response-system`（可自訂）→「建立」。
   4. 建立完成後，確認上方的專案選擇器已切換到這個新專案。
2. **啟用 Google Sheets API**
   1. 左側選單「API 和服務」→「程式庫」。
   2. 搜尋 `Google Sheets API` → 點進去 →「啟用」。
   3. 只需要 Sheets API；系統用網址中的文件 ID 直接存取，不需要 Google Drive API。
3. **建立服務帳號**
   1. 在 Google Sheets API 頁面點「建立憑證」（或左側「API 和服務」→「憑證」→「建立憑證」→「服務帳戶」）。
   2. 「憑證類型」頁面：
      - 「選取 API」：`Google Sheets API`
      - **「您要存取哪種資料？」選「應用程式資料」**（不要選「使用者資料」，原因見下方說明）
      - 按「下一步」。
   3. 「服務帳戶詳細資料」：名稱填 `crs-sheets`（可自訂），ID 會自動產生 →「建立並繼續」。
   4. 「授予這個服務帳戶專案存取權」：**不用選任何角色**，直接「繼續」→「完成」。
      服務帳號只需要存取你分享給它的試算表，不需要專案層級的權限。
4. **下載 JSON 金鑰**
   1. 左側「IAM 與管理」→「服務帳戶」，點剛建立的服務帳戶。
   2. 切到「金鑰」分頁 →「新增金鑰」→「建立新的金鑰」→ 類型選「JSON」→「建立」。
   3. 瀏覽器會自動下載一個 `.json` 檔，這就是金鑰。**金鑰只能下載這一次**，遺失要重新建立。
5. **把金鑰放到 repo 以外的位置**（避免誤 commit），並限制只有自己能讀：

   ```bash
   mkdir -p ~/.config/classroom-response-system
   ```

   ```bash
   mv ~/Downloads/<下載的金鑰檔名>.json ~/.config/classroom-response-system/service-account.json
   ```

   ```bash
   chmod 600 ~/.config/classroom-response-system/service-account.json
   ```

6. **記下服務帳號的 email**：在「服務帳戶」清單的「電子郵件」欄，格式像
   `crs-sheets@classroom-response-system.iam.gserviceaccount.com`；金鑰 JSON 裡的 `client_email` 也是同一個值。

> **為什麼選「應用程式資料」？**
> - **應用程式資料**：系統以服務帳號自己的身分存取資料。只要把試算表分享給服務帳號，系統啟動時用金鑰
>   就能讀寫，不需要任何人登入。這是 plan 選定的做法（[research.md](./research.md) R7）。
> - **使用者資料**：系統代替某位使用者存取他的資料，必須設定 OAuth 同意畫面、讓老師在瀏覽器登入
>   Google 並授權，系統還要保存每位使用者的授權 token。本專案只在本機模擬，不需要這種流程，也不想
>   多保存一份機敏資料。

> **金鑰等同密碼**：不要 commit、不要貼到聊天或文件裡。若不小心外流，到「服務帳戶」→「金鑰」刪除
> 該金鑰，再建立新的一把。

### 1.3 準備 Demo 用 Guided Notes 並分享給服務帳號

課程範例屬於課程所有，而且系統會寫入文件，所以要先複製到自己的雲端硬碟，只分享副本。

1. 開啟課程範例（連結見 [spec.md](./spec.md)「Demo 範例文件」）：「軟工期末專案_單題_範例」。
2. 選單「檔案」→「建立副本」→ 名稱可改成「CRS Demo 單題」→ 資料夾選「我的雲端硬碟」→「建立副本」。
3. 在副本中點右上角「共用」：
   1. 在「新增使用者」欄貼上 1.2 第 6 步的服務帳號 email。
   2. 權限選「**編輯者**」（匯出需要寫入）。
   3. **取消勾選「通知使用者」**（服務帳號收不到信）→「共用」。
4. 複製副本網址（瀏覽器網址列，形如 `https://docs.google.com/spreadsheets/d/<文件ID>/edit...`），
   之後在老師端匯入時貼上。
5. 對「軟工期末專案_題組_範例」重複 1～4，副本名稱可用「CRS Demo 題組」。

助教或其他人提供的 Guided Notes 也一樣：複製或取得編輯權後，分享給服務帳號 email（編輯者）即可匯入。
沒有分享時，匯入會顯示「無法存取文件」（`SHEETS_UNAVAILABLE`）。

### 1.4 設定檔

複製 `.env.example` 為 `.env` 並填入：

| 變數 | 說明 |
|------|------|
| `TEACHER_PASSWORD` | 老師端密碼（至少 8 字） |
| `SESSION_SECRET` | 簽章 token 用的隨機字串（至少 32 字），可用 `openssl rand -hex 32` 產生 |
| `GOOGLE_SERVICE_ACCOUNT_KEY_FILE` | 金鑰 JSON 的完整路徑，例如 `/Users/<你的帳號>/.config/classroom-response-system/service-account.json` |
| `PORT` | 選填，預設 3000 |
| `DATA_DIR` | 選填，預設 `./data` |

缺少必填變數或格式錯誤時，伺服器會拒絕啟動並說明是哪一個變數。`.env`、金鑰檔、`data/` 都不納入版控。

## 3. 自動化驗證（每個 Phase 結束時都必須全部通過）

```bash
npm run typecheck
```

```bash
npm run lint
```

```bash
npm test
```

自動化測試不連線 Google、不需要 `.env` 中的真實憑證。重點測試與對應需求：

| 測試 | 驗證內容 | 需求 |
|------|----------|------|
| 解析：單題範例 fixture | 辨識出題號 1～6、各 1 個作答格 | FR-007、FR-008、SC-001 |
| 解析：題組範例 fixture | 辨識出 4 題，第 1、2 題為題組（各 2 子題） | FR-009a、SC-001 |
| 解析：錯誤 fixtures | 每種錯誤代碼都被回報且帶位置，系統資料不變 | FR-010、SC-008 |
| 解析：變體 fixtures | `Q1`／全形題號、無標記題組、空白列、多工作表 | FR-006a、FR-007a |
| 狀態機 | 只允許規定的轉換，`CLOSED → OPEN` 被拒絕 | FR-012 |
| 並發順位 | 20 組同時送出同一題，重複 100 次，只有一個搶答成功 | FR-016、SC-005 |
| 可見性 | 活動結束前學生收到的資料不含他組作答與順位 | FR-020、SC-006 |
| 權限 | 學生 token 呼叫所有老師 API 皆被拒絕 | FR-002 |
| 分頁身分 | 不同 token 互不影響；重新連線收到完整狀態 | FR-003a、FR-014 |
| 匯出 | 只寫入搶答成功題目的作答格，題組保留標記，重複匯出結果相同 | FR-021～FR-024、SC-007 |
| 重啟恢復 | 重新建立服務並載入資料檔後，狀態、作答與順位相同 | FR-028、SC-010 |

## 4. 人工驗證清單（老師端＋兩組學生）

學生畫面在子功能 002 才會實作；本子功能以模擬腳本扮演學生，它使用與 002 相同的 API。

```bash
npm run simulate -- --group 1 --question 1 --answers "CPU" "作業系統"
```

（`--race` 參數可讓多組幾乎同時送出同一題，例如 `--race --groups 1,2 --question 3 --answers "0"`。）

準備：`npm start`；開兩個老師分頁 A、B（同一瀏覽器以「開新分頁」開啟，**不要用複製分頁**，
複製分頁會一併複製分頁身分）；另開一個終端機執行模擬腳本。

| # | 步驟 | 預期結果 | 需求 |
|---|------|----------|------|
| 1 | 分頁 A 輸入錯誤密碼 | 顯示密碼錯誤，不透露任何密碼資訊 | FR-003 |
| 2 | 分頁 A 輸入正確密碼 | 進入老師端，顯示「尚未匯入」 | FR-003 |
| 3 | 分頁 B 不登入直接開 `/teacher` | 要求輸入密碼（身分不與分頁 A 共用） | FR-003a |
| 4 | 分頁 A 貼上「題組範例」副本網址、組數 2，匯入 | 顯示 4 題，第 1、2 題標示題組（2 子題）；狀態「待開始」 | FR-008、FR-009a |
| 5 | 分頁 A 改匯入「單題範例」副本 | 顯示 6 題，取代先前題目 | FR-011 |
| 6 | 貼上一個非 Google Sheets 網址 | 顯示網址格式錯誤，題目不變 | FR-006a |
| 7 | 分頁 B 登入 | 看到與分頁 A 相同的狀態與題目 | FR-014 |
| 8 | 分頁 A 開啟搶答 | 分頁 A、B 在 1 秒內顯示「搶答進行中」 | FR-013、SC-003 |
| 9 | 終端機：第 1 組送出第 1 題 | 分頁 A、B 即時出現第 1 組的答案與順位 1 | FR-018 |
| 10 | 終端機：`--race` 讓第 1、2 組同時送出第 2 題 | 只有一組顯示為搶答成功，順位 1、2 不重複 | FR-016 |
| 11 | 終端機：第 2 組送出第 3 題，答案為空白 | 腳本顯示答案無效，老師端沒有新紀錄 | FR-017a |
| 12 | 重新整理分頁 A | 不需重新輸入密碼，畫面與資料不變 | FR-003a、FR-014 |
| 13 | 停止伺服器後再 `npm start`，重新整理分頁 A | 仍為「搶答進行中」，作答紀錄與順位不變 | FR-028、SC-010 |
| 14 | 分頁 A 結束搶答 | 分頁 A、B 顯示「已結束」與每題結果，無人作答的題目標示「無人搶答」 | FR-019 |
| 15 | 終端機：第 2 組再送出第 4 題 | 被拒絕（搶答已結束） | FR-015 |
| 16 | 分頁 A 嘗試再次開啟搶答 | 被拒絕，說明需重新匯入 | FR-012 |
| 17 | 分頁 A 匯出 | 顯示寫入題數；Google Sheets 中搶答成功題目的作答格出現答案，其他儲存格不變 | FR-021、FR-022、SC-007 |
| 18 | 再匯出一次 | 文件內容與上一步相同 | FR-024 |
| 19 | 換用「題組範例」副本重跑步驟 4、8～14、17 | 題組作答格寫成「（1）答案」「（2）答案」 | FR-021 |
| 20 | 在 Google Sheets 刪掉某個搶答成功題目的列後匯出 | 顯示無法定位的題號，文件沒有任何變更 | FR-023 |

## 5. 已知限制
