# Guided Notes 格式契約變更：題目敘述與匯出模式

**Feature**: `002-teacher-dashboard-enhancements` | 基準：[001 contracts/guided-notes-format.md](../../001-teacher-quiz-session/contracts/guided-notes-format.md)

001 的表頭、工作表選擇、題號、題組、標記與錯誤代碼規則（§1～§6）**全部不變**；題數、題型與填空格定位結果
MUST 與 001 相同。本文件新增 §A（讀取題目敘述）並以 §B 取代 001 §7（匯出規則）。

## §A0. 作答區與填答格（FR-025）

課程範例的實際版面：表頭「作答」橫跨 G:H 合併；單題的作答格是 G:H 合併的一格；題組每個子題列的 G 欄是
「（1）」「（2）」標記、H 欄是空白的填答格。規則如下（不寫死欄位，皆依表頭與合併範圍判斷）：

1. **作答區**：表頭列「作答」儲存格的合併欄範圍（沒有合併時就是那一欄）。
2. 對題目區塊的每一列，取作答區內各儲存格（合併時以左上角為準、同一格只算一次）：
   - 只有一格 → 這一格是**填答格**；子題標記（若有）讀自這一格的開頭，標記與答案同格。
   - 多於一格 → 內容為「（n）」標記的格是**標記格**（子題標記讀自它），標記格右側的第一格是填答格；
     都沒有標記時，作答區最左側的格為填答格。
3. 同一個填答格（跨列合併）只算一個填空格；填空格數 1 為單題、2 以上為題組（同 001 FR-009a）。
4. 標記規則（全部有或全部沒有、從（1）連號）沿用 001 §5，改為檢查標記格或填答格開頭的標記。

| 範例 | 預期 |
|------|------|
| 單題範例（真實版面） | 每題填答格為 G:H 合併的左上角 G 欄 |
| 題組範例（真實版面） | 題組子題的填答格為 H 欄，標記「（1）」「（2）」讀自 G 欄；單題的填答格為 G 欄 |
| 標記與答案同格的版面（作答區只有一欄） | 填答格為作答欄，標記讀自同一格，與 001 相同 |

## §A. 題目敘述（FR-001）

1. 在 001 找到的表頭列中，尋找內容恰為「題目」（忽略前後空白）的儲存格；其欄位（合併時為左上角所在欄）為
   **題目欄**。找不到時，所有題目與子題的敘述皆為 null，匯入照常成功，**不產生任何錯誤**。
2. 某一列的敘述 = 該列題目欄的有效值（位於合併範圍內時取左上角的值），去除前後空白；空字串視為沒有敘述。
3. 單題：題目區塊內各列的敘述依由上而下順序、去除重複後以換行合併 → `Question.prompt`。
4. 題組：
   - 每個子題的敘述 = 該子題作答格所在列的敘述 → `Blank.prompt`。
   - 區塊內不是任何子題作答格所在列的敘述，依序以換行合併 → `Question.prompt`（題組說明）；沒有則為 null。
5. 敘述只讀取文字內容，保留原有的換行，不保留字體、顏色等格式。

| 範例 | 預期 |
|------|------|
| 單題範例 | 6 題皆有 `prompt`（各為一句問句），`Blank.prompt` 皆為 null |
| 題組範例 | 第 1、2 題 `prompt` 為 null、兩個子題各有 `prompt`；第 3、4 題（單題）有 `prompt` |
| 沒有「題目」表頭的文件 | 匯入成功，所有敘述為 null，預覽顯示「文件未提供題目敘述」 |

## §B. 匯出規則（取代 001 §7；FR-017～FR-024）

### B.1 共通步驟

1. 重新讀取整份文件，依 001 §1～§6 重新解析並定位（不使用匯入時保存的位置），同時取得表頭列、使用範圍欄數與
   既有結果欄（§B.3）。
2. 對每個搶答成功的題目依題號找到同一題；找不到或子題數不同 → 無法定位。
3. 有任何無法定位的題目 → `EXPORT_LOCATE_FAILED`（列出題號），**不寫入任何儲存格**。
4. 依所選模式產生完整寫入清單後，以**單一批次**寫入。所有值都以純文字寫入（不會被解析成公式、數字或日期）。
5. 所選模式規定的儲存格以外，文件內容一律不動；儲存格的框線、底色、對齊等格式不改動。

### B.2 答案值（三種模式共用，FR-025）

答案一律寫入 §A0 的填答格：

- 單題：`答案`
- 題組子題：標記在獨立的標記格 → `答案`（標記格不動）；標記與答案同格 → `標記原文 + 答案`（例如 `（1）CPU`，同 001）；
  沒有標記 → `答案`

### B.3 模式

| 模式 | 寫入內容 |
|------|----------|
| `answers-only`（只有答案） | 搶答成功題目的每個填答格寫入答案值，並清除該格內的局部文字樣式（例如先前附註行的灰色小字） |
| `answers-with-columns`（答案＋組別時間欄） | 作答格同上；另以「搶答組別」「提交時間」兩欄記錄結果（見下方） |
| `answers-with-note-line`（答案＋格內附註行） | 作答格寫入 `答案值 + 換行 + 〔第 N 組｜提交時間〕`；換行起的部分以較小灰色字顯示。單題寫在該題填答格；題組只寫在**最後一個**子題的填答格，其他子題只有答案值 |

**答案＋組別時間欄的定位：**

1. 在表頭列尋找內容恰為「搶答組別」「提交時間」的儲存格，找到即沿用該欄。
2. 缺少的欄依「搶答組別」「提交時間」的順序，新增在使用範圍最右側之後的第一個空白欄（使用範圍 = 所有列最後
   一個非空白儲存格與所有合併範圍的最右欄），並在表頭列寫入欄名。工作表欄數不足時先補足欄數。
3. 每一題寫在「題目區塊第一列」（該題所有作答格中最上方的列）：
   - 搶答成功：`第 N 組` 與 `YYYY/MM/DD HH:mm:ss.SSS`（執行系統的電腦所在時區）。
   - 無人搶答：兩格清空。
4. 這兩欄中不屬於任何題目區塊第一列的儲存格不動。題組的組別與時間只寫一次。

**提交時間** = 搶答成功作答的伺服器收件時間，格式 `YYYY/MM/DD HH:mm:ss.SSS`。

### B.4 可重複與重新匯入

- 同一模式重複匯出 → 寫入的值與樣式完全相同：結果欄依表頭名稱沿用，不重複新增；附註行所在格整格覆寫，不累加。
- 改用其他模式匯出：作答格依新模式整格覆寫（附註行隨之消失）；先前新增的結果欄不會自動刪除。
- 匯出後重新匯入：結果欄的表頭不是「題號」「作答」，不影響表頭判斷；附註行位於作答格第二行之後，不影響
  開頭「（n）」標記的判斷；題數與定位結果與匯出前相同（FR-023）。

### B.5 範例（題組範例真實版面，第 1 題由第 2 組於 2026/11/23 10:32:15.123 搶答成功）

G 欄的「（1）」「（2）」標記在三種模式下都不變。

| 模式 | 第 1 題子題 1 填答格（H5） | 第 1 題子題 2 填答格（H6） | 結果欄（題目區塊第一列，I5／J5） |
|------|--------------------------|--------------------------|--------------------------|
| 只有答案 | `CPU` | `作業系統` | — |
| 答案＋組別時間欄 | `CPU` | `作業系統` | 搶答組別：`第 2 組`；提交時間：`2026/11/23 10:32:15.123` |
| 答案＋格內附註行 | `CPU` | `作業系統`⏎`〔第 2 組｜2026/11/23 10:32:15.123〕`（第二行為灰色小字） | — |

標記與答案同格的版面（作答區只有一欄）則沿用 001：`（1）CPU`、`（2）作業系統`。
