# Feature Specification: 介面視覺與互動體驗改版

**Feature Branch**: `007-ui-ux-refresh`

**Created**: 2026-11-28

**Status**: Draft

**Input**: User description: "UI/UX增進 不要像現在一樣太單調"

## 範圍說明

001～006 完成了老師端與學生端的完整搶答流程，但畫面幾乎全部是白底卡片、灰色文字與同一種藍色按鈕：
首頁只有標題和兩個色塊按鈕；各組只用「第 N 組」文字區分；活動階段只靠一個小標籤；送出成功、搶答成功、
階段切換都沒有明顯回饋；等待與空白狀態只有一行灰字。課堂搶答是帶有競賽感的活動，畫面太平淡會讓學生
缺少參與感，也讓老師與學生不容易一眼看出「現在是什麼階段、哪一組、誰搶到了」。本子功能在不改變任何
流程與規則的前提下，改善整個系統的視覺與互動體驗。

**本子功能包含**：

- 一套全站共用的視覺風格（配色、字級層次、卡片層次、按鈕狀態、圖示），取代目前的預設灰白樣式
- 首頁改版：系統名稱、簡短說明，以及附圖示與說明的「老師端」「學生端」入口
- 每個組別有固定的專屬識別（顏色＋圖示），出現在所有顯示組別的地方
- 活動階段一眼可辨：依階段改變強調色，階段切換時顯示短暫的切換提示
- 操作與結果回饋：送出中、送出成功、搶答成功名次標示與慶祝效果
- 等待、空白、載入與連線中斷狀態的視覺化呈現
- 尊重「減少動態效果」的系統設定，以及基本的可及性與不同螢幕寬度的版面
- 改版範圍涵蓋所有畫面：首頁、老師登入頁、老師主畫面（匯入、題目、活動控制、送出列表、Guided Notes 與 CSV 匯出、
  分組情況面板）與學生端所有畫面（暱稱、選組、作答、結果）

**本子功能不包含**：

- 任何流程、規則或資料可見性的改變：加入與離開組別、作答與送出、搶答判定、名次、匯入與匯出（Guided Notes、CSV）
  的行為全部維持 001～006 的定義
- 既有按鈕文字、提示訊息與螢幕閱讀器名稱的改寫（本 spec 明列新增的文字除外）
- 深色模式、讓老師或學生自選主題或配色
- 讓老師自訂各組的顏色、圖示或組名
- 多語系
- 音效（任何畫面都不播放聲音）
- 排行榜、積分、連勝等新的遊戲機制

## Clarifications

### Session 2026-11-28

- Q: 改版要涵蓋哪些畫面？ → A: 首頁、老師端、學生端全部（範圍說明、FR-009）。
- Q: 視覺風格要偏向哪一種？ → A: 活潑遊戲感：鮮豔多色、圓潤大按鈕、動畫明顯；老師端與學生端採用同一種風格（FR-002）。
- Q: 要不要加音效？ → A: 不加，任何畫面都不播放聲音（FR-022、範圍說明）。
- Q: 搶答結束時，老師端要不要有「結果揭曉」畫面？ → A: 要；結束時老師端顯示一次結果揭曉畫面，列出每題搶答成功的組別，
  老師按關閉後回到主畫面，重新整理後不重播；老師端不播放慶祝效果（FR-029）。
- Q: 學生加入組別後，學生端畫面要帶多少本組顏色？ → A: 頂端列底色用本組顏色、組員名單卡片有本組顏色邊條；
  活動階段改由頂端列內的階段標籤（強調色＋圖示）表示，頁面背景維持全站共用色（FR-009a、FR-011）。
- Q: 改版好不好、看不看得清楚，要用哪種方式驗收？ → A: 全部改成可勾選的檢查項目，不做試用者評分與改版前後計時
  （SC-001～SC-003、Assumptions）。
- Q: 搶答進行中，老師端送出列表收到新送出時要不要有動態效果？ → A: 要；新送出短暫滑入並亮起，1 秒內結束，多筆同時到達
  一起出現、不排隊；首次載入或重新整理時已存在的送出不播放；分組情況面板不加動態（FR-030）。
- Q: 學生端慶祝效果要播多久、會不會擋住結果畫面？ → A: 效果疊在畫面上方，3 秒內自動結束，不攔截點擊，結果畫面一開始
  就可以看、可以捲動（FR-019）。
- Q: 老師結束搶答時，結果畫面要立刻出現還是等「搶答結束」提示消失？慶祝效果與結果揭曉何時出現？ → A: 結果畫面立刻出現，
  提示疊在上方；學生端慶祝效果與老師端結果揭曉畫面都在提示消失後才出現，同一時間只有一個效果（FR-012、FR-019、FR-029）。
- Q: 組別圖示旁要不要顯示圖示名稱（例如「第 3 組・火箭」）？ → A: 不要；只顯示圖示，組名仍是「第 N 組」，螢幕閱讀器也只念
  「第 N 組」，圖示不另外朗讀（FR-007、FR-027）。
- Q: 老師端結果揭曉畫面要不要顯示搶答成功的答案內容？ → A: 要；每題列出組別識別、送出者暱稱，下面每個子題一行
  「（n）答案」，長答案自動換行，題目多時畫面可以捲動（FR-029）。
- Q: 學生沒在結束當下看到畫面變化（例如斷線，重連後直接進結果畫面），本組有搶到題目時還要播慶祝效果嗎？ → A: 不播；
  統一規則為「分頁當場看到階段由搶答進行中變為已結束才出現」，切換提示、慶祝效果、老師端結果揭曉都相同，不另外記錄播放過與否
  （FR-019、Key Entities）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全站一致且有層次的視覺風格 (Priority: P1)

老師與學生打開系統的任何畫面，看到的是同一套有主色、有層次的介面：背景與卡片分得清楚，標題、內文、
輔助說明的字級有明顯差別，主要操作、次要操作與危險操作的按鈕一眼可辨。首頁顯示系統名稱與一句說明，
「老師端」「學生端」兩個入口各有圖示與一句用途說明。

**Why this priority**: 這是「不單調」最直接的改變，其他故事（組別識別、階段提示、回饋）都建立在這套共用風格上。

**Independent Test**: 依序打開首頁、老師登入頁、老師主畫面、學生暱稱頁、選組頁、作答頁、結果頁，確認每個畫面
都使用同一套配色與按鈕樣式，背景不是純白，首頁兩個入口都有圖示與說明。

**Acceptance Scenarios**:

1. **Given** 使用者打開首頁，**When** 畫面載入完成，**Then** 顯示系統名稱、一句系統說明，以及「老師端」「學生端」
   兩個入口；每個入口有圖示與一句用途說明（老師端：匯入題目、控制搶答；學生端：輸入暱稱、選組作答）。
2. **Given** 使用者在任一畫面，**When** 檢視主要按鈕、次要按鈕與危險操作按鈕（如結束搶答、離開組別），
   **Then** 三種按鈕外觀不同，且滑鼠移上、按下、停用、處理中都有可見的變化。
3. **Given** 使用者在任一畫面，**When** 比較背景與內容卡片，**Then** 背景帶有色調或淡圖樣，卡片與背景有明顯層次。

---

### User Story 2 - 每個組別都有專屬識別 (Priority: P1)

學生選組時，每個組別按鈕都有自己的顏色與圖示；加入後，頂端列底色換成本組顏色、組員名單卡片有本組顏色邊條，結果畫面也帶著本組的顏色與圖示。
老師在送出列表與分組情況面板上，看到每筆送出、每個組別也帶著同樣的識別，不必逐字讀「第 N 組」就能辨認。

**Why this priority**: 組別是搶答活動的基本單位，專屬識別同時增加參與感（學生一眼認得「我們這組的顏色和圖示」）與辨識速度。

**Independent Test**: 匯入題目後設定 20 組，打開學生端選組畫面，確認 20 個組別的顏色＋圖示組合都不相同；
加入第 3 組送出一題，確認學生端頂端列與老師端送出列表、分組情況面板中第 3 組的顏色與圖示一致。

**Acceptance Scenarios**:

1. **Given** 活動有 N 組（2 ≤ N ≤ 20），**When** 學生打開選組畫面，**Then** 每組顯示專屬顏色與圖示，
   且任兩組的「顏色＋圖示」組合不重複，組別名稱與已加入人數仍然顯示。
2. **Given** 學生已加入第 3 組，**When** 檢視頂端列、組員名單與結果畫面，**Then** 頂端列底色為第 3 組的顏色並顯示第 3 組圖示，
   組員名單卡片有第 3 組顏色的邊條，結果畫面顯示第 3 組的顏色與圖示。
3. **Given** 第 3 組送出答案，**When** 老師檢視送出列表與分組情況面板，**Then** 第 3 組的識別與學生端相同。
4. **Given** 老師重新匯入題目或重新整理頁面，**When** 再次檢視各組，**Then** 同一組別編號的識別保持不變。

---

### User Story 3 - 活動階段一眼可辨，切換時有提示 (Priority: P2)

學生在作答頁時，頂端列內的階段標籤隨活動階段改變：待開始、搶答進行中、已結束各有不同的強調色與圖示（頂端列底色固定為本組顏色）。老師按下
開始搶答的那一刻，所有學生分頁都短暫出現「搶答開始！」的提示；結束時出現「搶答結束」的提示。提示會自己
消失，不需要點擊，也不擋住作答。

**Why this priority**: 階段決定學生能做什麼；醒目的階段呈現與切換提示讓學生不會錯過開始，也強化競賽感。

**Independent Test**: 開一個老師分頁與兩個學生分頁，老師開始搶答，確認兩個學生分頁都出現「搶答開始！」提示並在
2 秒內自動消失、階段標籤換成進行中的強調色與圖示；老師結束搶答，確認出現「搶答結束」提示。重新整理學生分頁，提示不重播。

**Acceptance Scenarios**:

1. **Given** 學生在作答頁且階段為「待開始」，**When** 老師開始搶答，**Then** 學生分頁顯示「搶答開始！」切換提示，
   提示在 2 秒內自動消失，期間可以直接開始作答，頂端列內的階段標籤改為「搶答進行中」的強調色與圖示。
2. **Given** 階段為「搶答進行中」，**When** 老師結束搶答，**Then** 學生分頁立刻切換到結果畫面，「搶答結束」切換提示疊在上方，
   2 秒內自動消失。
3. **Given** 階段為「搶答進行中」，**When** 學生重新整理分頁或斷線重連，**Then** 直接回到進行中畫面，不重播切換提示。
4. **Given** 老師在老師端開始或結束搶答，**When** 階段改變，**Then** 老師端的階段標示同樣改變強調色，並顯示相同的切換提示。

### User Story 4 - 送出與結果有明顯回饋 (Priority: P2)

學生按下送出後，按鈕立即顯示處理中；送出成功時該題出現明顯的成功標記與短暫動畫。搶答結束後，結果畫面以
獎盃標示每題搶答成功的組別；如果本組搶到任何一題，學生端播放一次慶祝效果。老師端送出列表以金、銀、銅標示
每題的第 1、2、3 名，並在結束時顯示一次「結果揭曉」畫面，列出每題搶答成功的組別。

**Why this priority**: 回饋讓學生確定動作已完成，名次與慶祝則是搶答活動最有感的時刻。

**Independent Test**: 學生送出一題，確認處理中與成功標記；老師端確認第 1～3 名的金銀銅標示；結束搶答後，搶答成功
的組別看到慶祝效果，其他組只看到結果與獎盃標示。

**Acceptance Scenarios**:

1. **Given** 搶答進行中，**When** 學生按下送出，**Then** 按鈕立即顯示處理中且不能重複按，成功後該題顯示成功標記與短暫動畫。
2. **Given** 某題有三組以上送出，**When** 老師檢視送出列表，**Then** 第 1、2、3 名分別有金、銀、銅標示，其餘名次維持一般樣式。
3. **Given** 搶答已結束且本組搶到至少一題，**When** 學生進入結果畫面，**Then** 播放一次慶祝效果，3 秒內自動結束，播放期間
   結果畫面可以直接閱讀與捲動，搶到的題目有獎盃標示。
4. **Given** 搶答已結束且本組沒有搶到任何一題，**When** 學生進入結果畫面，**Then** 不播放慶祝效果，仍以獎盃標示他組
   搶答成功的答案（依既有可見性規則）。
5. **Given** 學生已看過慶祝效果，**When** 重新整理結果畫面，**Then** 不再重播。
   **Given** 學生分頁在老師結束搶答時斷線，**When** 重連後直接進入結果畫面，**Then** 不播放慶祝效果，獎盃標示照常顯示。
6. **Given** 老師按下結束搶答，**When** 階段變為「已結束」，**Then** 老師端顯示「結果揭曉」畫面，依題號列出每題搶答成功的
   組別識別、送出者暱稱與答案（每個子題一行「（n）答案」），無人送出的題目顯示「本題無人搶答」；老師按「關閉」後回到主畫面。
7. **Given** 老師已關閉結果揭曉畫面，**When** 重新整理老師端，**Then** 不再顯示結果揭曉畫面。
8. **Given** 搶答進行中，**When** 有組別送出答案，**Then** 老師端送出列表中新的一筆以短暫滑入並亮起的方式出現，1 秒內結束；
   **When** 老師重新整理老師端，**Then** 已存在的送出直接顯示，不播放動態。

### User Story 5 - 等待、空白與連線狀態不再只是一行灰字 (Priority: P3)

老師尚未匯入題目、等待老師開始、某題尚無送出、無人搶答成功、載入中、連線中斷等狀態，都以圖示或插圖加上
一句說明呈現；等待類畫面有輕量的循環動態，讓使用者知道系統仍在運作。連線中斷時出現醒目但不遮擋操作的提示，
恢復後短暫顯示「已重新連線」。

**Why this priority**: 這些狀態出現頻率高但不影響流程，改善後能讓等待時間不顯得空洞。

**Independent Test**: 在老師尚未匯入時打開學生端、在待開始時加入組別、關閉伺服器再重啟，確認各狀態都有圖示與說明、
等待中有動態、連線中斷與恢復都有提示。

**Acceptance Scenarios**:

1. **Given** 老師尚未匯入題目，**When** 學生打開選組畫面，**Then** 顯示等待插圖、既有說明文字「老師尚未匯入題目，請稍候」與輕量動態。
2. **Given** 學生已加入組別、階段為待開始，**When** 檢視作答頁，**Then** 顯示等待老師開始的圖示與說明。
3. **Given** 學生或老師分頁與伺服器斷線，**When** 連線中斷，**Then** 顯示醒目的中斷提示且不遮擋操作；**When** 連線恢復，
   **Then** 短暫顯示「已重新連線」後消失。

---

### Edge Cases

- 活動有 20 組時，組別識別仍兩兩不同；顏色數量不足時以不同圖示區分，並一律同時顯示組別名稱。
- 老師開始搶答後很快又結束：切換提示只顯示最新的階段，不排隊連續播放。
- 學生在切換提示顯示期間送出答案：提示不攔截點擊，送出照常進行。
- 20 組幾乎同時送出：老師端送出列表的新送出一起滑入，不逐筆排隊，名次與金銀銅標示仍即時正確。
- 本組搶到多題：慶祝效果只在看到結束的當下播放一次。
- 學生分頁在結束當下斷線、之後重連進入結果畫面：不播放慶祝效果，也不顯示「搶答結束」提示，結果與獎盃標示照常顯示。
- 老師在結果揭曉畫面尚未關閉時重新整理：不再顯示揭曉畫面，直接回到主畫面（已結束）。
- 結果揭曉畫面開著時，老師從另一個老師分頁重新匯入題目（開始新的一場）：揭曉畫面自動關閉，新的一場結束時再顯示一次。
- 搶答結束時，同一時間只有一個效果：先是「搶答結束」提示，提示消失後才是學生端慶祝效果或老師端結果揭曉。
- 同一台電腦並列多個老師與學生分頁：各分頁的提示與慶祝效果各自播放，互不影響。
- 系統設定為「減少動態效果」：切換提示改為靜態出現與消失，慶祝效果與循環動態不播放，資訊仍完整呈現。
- 長暱稱（20 字）與長答案在新樣式下仍正常換行，不超出卡片或與其他元素重疊。
- 手機寬度（375 px）到大螢幕（1920 px）都不出現水平捲動。
- 沒有網際網路的教室環境：所有圖示、插圖與字型照常顯示。
- 色弱使用者：階段、組別、名次都同時以文字或圖示表達，不只依賴顏色。

## Requirements *(mandatory)*

### Functional Requirements

**共用視覺風格（US1）**

- **FR-001**: 系統 MUST 定義一套全站共用的視覺風格，包含主色、輔助色、語意色（成功、警告、錯誤、資訊）、
  字級層次、圓角、陰影與間距，並套用到改版範圍內的所有畫面。
- **FR-002**: 視覺風格 MUST 為「活潑遊戲感」，老師端與學生端採用同一種風格：配色以多種鮮豔顏色搭配（不以單一主色為主），
  卡片與按鈕為明顯的圓角，主要操作按鈕比一般文字明顯更大；切換提示、送出成功、慶祝效果等動畫要明顯可見，
  但仍受 FR-013、FR-023、FR-028 的限制（不擋操作、可減少動態、不拖慢操作）。
- **FR-003**: 頁面背景 MUST 帶有色調或淡圖樣，內容卡片與背景 MUST 有明顯可區分的層次。
- **FR-004**: 按鈕 MUST 分為主要、次要、危險三種外觀；每種按鈕的滑鼠移上、按下、停用、處理中狀態 MUST 有可見差異。
- **FR-005**: 首頁 MUST 顯示系統名稱、一句系統說明，以及「老師端」「學生端」兩個入口；每個入口 MUST 有圖示與一句用途說明。
- **FR-006**: 系統 MUST 使用一致的圖示語言：同一種意義（例如送出成功、搶答成功、等待、連線中斷）在所有畫面使用同一個圖示。

**組別識別（US2）**

- **FR-007**: 每個組別 MUST 有依組別編號固定指派的專屬識別（一個顏色與一個圖示），同一組別編號在任何活動、
  重新匯入或重新整理後都相同。圖示只作視覺識別：畫面上 MUST NOT 顯示圖示名稱，螢幕閱讀器 MUST NOT 朗讀圖示，
  組名與朗讀名稱仍為「第 N 組」。
- **FR-008**: 在 2～20 組的範圍內，任兩組的「顏色＋圖示」組合 MUST NOT 重複；組別識別 MUST 與組別名稱一起顯示，
  不可只靠顏色辨認。
- **FR-009**: 組別識別 MUST 出現在：學生端選組按鈕、學生端頂端列、學生端組員名單、學生端結果畫面、
  老師端送出列表的每筆送出、老師端分組情況面板。
- **FR-009a**: 學生加入組別後，學生端頂端列底色 MUST 為本組顏色並顯示本組圖示，組員名單卡片 MUST 有本組顏色的邊條；
  頁面背景 MUST 維持全站共用色，不隨組別改變。

**活動階段（US3）**

- **FR-010**: 活動階段（尚未匯入、待開始、搶答進行中、已結束）MUST 各有不同的強調色與圖示，並保留既有的階段文字。
- **FR-011**: 學生端頂端列內的階段標籤與老師端階段標示 MUST 依目前階段套用對應的強調色與圖示；學生端頂端列底色固定為
  本組顏色（FR-009a），不隨階段改變，階段標籤與本組顏色的底色之間 MUST 符合 FR-024 的對比要求。
- **FR-012**: 階段由「待開始」變為「搶答進行中」時，MUST 顯示「搶答開始！」切換提示；由「搶答進行中」變為「已結束」時，
  MUST 顯示「搶答結束」切換提示。切換提示疊在新階段的畫面上方，畫面本身 MUST 立刻切換，不等提示消失（例如結束時結果畫面
  立刻出現）。
- **FR-013**: 切換提示 MUST 在 2 秒內自動消失、MUST NOT 需要點擊關閉、MUST NOT 攔截畫面上的操作，且只反映伺服器推播的階段。
- **FR-014**: 分頁重新整理、首次載入或斷線重連後進入某個階段時，MUST NOT 播放切換提示；短時間內連續切換時只顯示最新階段的提示。

**送出與結果回饋（US4）**

- **FR-015**: 學生按下送出後，送出按鈕 MUST 立即顯示處理中狀態且不能重複送出；送出成功後該題 MUST 顯示成功標記與短暫動畫。
- **FR-016**: 搶答進行中的計時 MUST 以動態方式呈現正在計時（例如顏色與脈動指示），結束後定格並改為結束樣式。
- **FR-017**: 老師端送出列表 MUST 以金、銀、銅標示每題的第 1、2、3 名；第 4 名之後維持一般樣式。
- **FR-030**: 搶答進行中，老師端送出列表收到新的送出時，該筆 MUST 以短暫滑入並亮起的方式出現，並在 1 秒內結束；
  同時到達的多筆 MUST 一起出現、不排隊；首次載入、重新整理或重連時已存在的送出 MUST NOT 播放；分組情況面板不加此動態。
  減少動態效果時直接出現。
- **FR-018**: 學生端結果畫面 MUST 以獎盃標示每題搶答成功的答案，標示範圍完全依照既有可見性規則，不提前或額外透露其他組的資料。
- **FR-019**: 若本組搶到至少一題，學生端 MUST 在本分頁看到階段由「搶答進行中」變為「已結束」時播放一次慶祝效果；本組沒有
  搶到任何題目時 MUST NOT 播放；首次載入、重新整理或斷線重連後進入「已結束」時 MUST NOT 播放。慶祝效果 MUST 在「搶答結束」切換提示消失後才開始，疊在結果畫面上方、
  MUST NOT 攔截點擊或捲動，並在開始後 3 秒內自動結束。
- **FR-029**: 老師端在本分頁看到階段由「搶答進行中」變為「已結束」時，MUST 在「搶答結束」切換提示消失後顯示一次「結果揭曉」
  畫面：依題號列出每題搶答成功的組別識別（FR-007）、送出者暱稱與答案，答案沿用送出列表的排版（每個子題一行「（n）答案」、
  長答案自動換行），無人送出的題目顯示「本題無人搶答」，題目多時畫面內可以捲動；畫面 MUST 有「關閉」
  按鈕，關閉後回到主畫面；首次載入、重新整理或重連後進入「已結束」時 MUST NOT 顯示；老師端 MUST NOT 播放慶祝效果。
  減少動態效果時，揭曉畫面以靜態方式出現。

**等待、空白與連線狀態（US5）**

- **FR-020**: 尚未匯入、等待開始、某題尚無送出、無人搶答成功、載入中等狀態 MUST 以圖示或插圖加上說明文字呈現，
  並保留既有的說明文字；等待類狀態 MUST 有輕量的循環動態。
- **FR-021**: 連線中斷時 MUST 顯示醒目且不遮擋操作的提示（保留既有文字）；連線恢復時 MUST 短暫顯示「已重新連線」後自動消失。

**音效**

- **FR-022**: 系統 MUST NOT 播放任何音效；所有回饋（階段切換、送出成功、搶答成功）只以畫面呈現。

**動態、可及性與版面**

- **FR-023**: 使用者的系統設定為「減少動態效果」時，系統 MUST 停用所有非必要動畫：切換提示改為靜態顯示、慶祝效果與
  循環動態不播放，資訊仍完整呈現。
- **FR-024**: 一般文字與背景的對比 MUST 至少 4.5:1，大字與圖示至少 3:1；所有可操作元件 MUST 能以鍵盤操作，並有清楚可見的焦點樣式。
- **FR-025**: 改版範圍內的畫面在 375 px 到 1920 px 的視窗寬度下 MUST NOT 出現水平捲動或文字、元件互相重疊；
  006 的分組情況面板寬窄版面規則維持不變。
- **FR-026**: 所有圖示、插圖與字型 MUST 隨系統一起提供，在沒有網際網路的環境也能完整顯示。

**行為不變**

- **FR-027**: 本子功能 MUST NOT 改變任何流程、規則、伺服器資料或資料可見性；既有按鈕文字、提示訊息與螢幕閱讀器名稱
  MUST 保持不變（FR-005、FR-012、FR-021、FR-029 新增的文字除外）。
- **FR-028**: 動畫與視覺效果 MUST NOT 讓操作變慢：搶答進行中按下送出到顯示處理中狀態的反應時間不因改版而增加。

### Key Entities *(include if feature involves data)*

- **視覺主題（Visual Theme）**：全站共用的配色、語意色、字級、圓角、陰影、間距與按鈕狀態定義；只存在於前端呈現，不新增伺服器資料。
- **組別識別（Group Identity）**：組別編號對應的固定顏色與圖示，2～20 組兩兩不同；由組別編號推得，不需儲存或設定。
- **階段樣式（Phase Style）**：每個活動階段對應的強調色、圖示與切換提示文字。
- **階段變化**：分頁收到伺服器推播、且與本分頁上一次看到的階段不同時，才觸發切換提示、慶祝效果、老師端結果揭曉與新送出動態；
  分頁第一次收到的資料（首次載入、重新整理、重連）不算變化。只存在於該分頁的記憶中，不需儲存。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 改版範圍內的每個畫面都通過共用風格檢查：背景不是純白、卡片與背景有層次、主要／次要／危險三種按鈕外觀不同
  且四種狀態都有可見變化、首頁兩個入口都有圖示與用途說明，未通過的畫面數為 0。
- **SC-002**: 學生端作答畫面與老師端主畫面上，四個活動階段的標籤強調色與圖示兩兩不同，且階段文字一直顯示。
- **SC-003**: 設定 2、10、20 組時，所有顯示組別的畫面中任兩組的「顏色＋圖示」組合都不重複，且同一組在學生端與老師端的
  識別完全相同。
- **SC-004**: 老師開始或結束搶答後，所有學生分頁在 1 秒內出現對應的切換提示。
- **SC-005**: 既有自動化測試全部通過，001～006 的人工驗證步驟全部通過，流程與規則零退化。
- **SC-006**: 改版範圍內所有畫面的文字對比全數達到 FR-024 的標準；在「減少動態效果」設定下，非必要動畫數為 0。
- **SC-007**: 在 375 px、768 px、1280 px、1920 px 四種寬度下，所有改版畫面都沒有水平捲動或元件重疊。
- **SC-008**: 在斷開網際網路的電腦上，所有圖示、插圖與字型都正常顯示。

## Assumptions

- 本子功能只改前端呈現，不新增或修改伺服器端資料、事件與 API；所有判斷（階段、名次、搶答成功）都沿用伺服器既有推播的資料。
- 組別識別依組別編號固定指派（例如第 1 組永遠是同一個顏色與圖示），老師不需設定，也不能自訂。
- 慶祝效果與獎盃標示只在學生依既有規則已經看得到結果時出現，不改變 003／004 的可見性規則。
- 學生可能使用手機或筆電，老師主要使用筆電或投影；不另外設計投影專用模式。
- 不做深色模式；介面依淺色主題設計。
- 「不單調」不以試用者評分或改版前後計時衡量，改以 SC-001～SC-003 等可勾選的檢查項目驗收，組員一人即可完成人工驗證。
- 為了視覺效果新增的圖示、插圖與字型以隨系統提供的方式加入，並沿用 004 的做法避免讓首頁與老師端初次載入明顯變慢。
